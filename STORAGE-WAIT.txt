Storage wait spinner and owner-window restoration

Waiting for storage now uses a small animated spinner beside the fixed message
"Waiting for storage...". It no longer shows a progress bar or copy fields.
After five seconds, "The drive is taking longer than usual." appears below it.
The dialog reserves space for this explanation so nothing moves when it appears.
The timer and explanation remain continuous across reads in one storage action.
The next action starts with a fresh delay. Copy progress retains its own layout.

The spinner is drawn with system colors in a small offscreen buffer. Only its
own control is repainted during animation; the status text is not rewritten on
each read. The dialog still uses the normal MFC message loop during slow I/O.

Both copy and storage-wait completion now restore the owner's enabled state
before destroying the dialog. If the dialog or owner was the foreground window,
completion requests activation of the owner and restores its saved keyboard
focus. If another application was foreground, no activation request is made.
An originally disabled owner stays disabled. The owner state is checked again
after MFC modal teardown. A retained native-wait session is closed before a full
copy job opens, preventing a nested copy from inheriting a disabled owner.

Validation: Release/Test builds and synthetic storage, copy and floppy tests
passed. Tests cover the spinner-only control layout, animation timer, fixed
message, delayed explanation appearing once across nested reads, delay reset,
owner restoration before dialog destruction, foreground-activation policy,
success/error/exception/cancellation completion and disabled-owner preservation.
The explanation delay is shortened only for hidden automated tests.
No computer control or physical media was used. Actual desktop activation and
the final appearance still require a manual check on your system.

Extract this build into a fresh folder and run HFVExplorer.exe after closing
the older version. Try opening a slow drive and completing a copy; HFVExplorer
should stay in front when its dialog was active. Switching to another app while
waiting should leave that app in front after the operation completes.

Changes are committed locally; no push performed. Native DPI experiment changes are excluded.

Compact layout update: storage-wait client area reduced from 280 x 66 to
220 x 50 dialog units, with tighter spacing and a smaller spinner. Space for
the delayed explanation remains reserved. This resource-only change built
successfully; the included regression results are from the prior build.


The measured-width experiment has been reverted. The fixed 220 x 50 dialog-unit
layout is restored, including reserved space for the delayed explanation.
Startup/media checks retain the matching spinner layout. Regression tests passed.

Spinner visibility fix: the spinner now paints through its own static-control
window, using a local animation timer and double buffering. Dots have a four-
pixel minimum: the previous three-pixel null-pen ellipses produced no visible
fill in the regression test despite successful GDI draw calls. Dialog size,
status text and delayed explanation are unchanged. Hidden offscreen rendering
tests now verify visible pixels and distinct animation frames; all storage,
CD image and floppy regressions passed. No computer control was used.
