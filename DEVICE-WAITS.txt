HISTORICAL DESIGN - SUPERSEDED
This document describes an earlier implementation. See STORAGE-WORKER.txt,
STORAGE-WAIT.txt and CHANGED-TRACK-COPY.txt for the current implementation.

RESPONSIVE REMOVABLE-MEDIA WAITS
Branch: image-only-x64. Native DPI experiment is not included.

Blocking native CD/floppy open, control, seek, read and close calls now execute
on a worker when called from the application interface thread. During waits,
the interface services painting and Windows sent messages every 50 ms instead
of blocking inside the driver. Probes, simulated storage tests and the existing
format/write worker continue using synchronous calls on their own thread.

The old HFS code and its global mount/descriptor state remain serialized.
App commands are temporarily disabled during device waits, and commands/timers
are deferred rather than dispatched back into the filesystem. Media-change
notifications received during waits schedule a refresh after the outer action.
A second device transaction from a paint callback is rejected with ERROR_BUSY.
Errors, handle failures, disabled-window state and shutdown messages are preserved.

This does not shorten spin-up time or cancel a stalled Windows driver request.
The window should keep repainting rather than becoming a ghost/not-responding
window; disk commands still wait for the current request to finish. This targets
the native Mac CD/floppy transport, not every legacy Windows-file dialog or
third-party shell extension.

Validation:
Release and Test builds passed. A hidden-window test with synthetic slow I/O
verified painting during waits, command deferral, reentrancy rejection, original
Windows errors/invalid handles, enabled-state restoration, exception cleanup,
preserved quit messages, and direct execution on an existing worker.
Simulated floppy writer/read-only and headless GUI-storage checks passed.
CD fixtures covering raw HFS, 512/2048-byte partition maps, mapless hybrids and
shortened partitions passed, including extraction, EOF, write rejection and
unchanged media. No physical drives or computer control were used.

Manual test:
Extract to a new folder and run this HFVExplorer.exe. Let the drive spin down,
then refresh or browse the existing HFS CD/floppy. Compare repainting during
the wait. No formatting or rewriting is needed.
DEVICE WAIT REDRAW FIX
The first responsive-wait build disabled/re-enabled the main window and restored
focus around every individual driver call. That caused repeated selection and
menu redraws when a CD operation performed many reads.

The app now batches UI state across one dispatched user action (or startup).
The first driver call disables the relevant windows; subsequent calls keep that
state stable. Window state and focus are restored once after the action finishes.
Nested modal message pumps release the previous action before waiting for input,
so dialogs cannot remain disabled. Paint servicing and worker I/O remain enabled.

Release/Test builds and simulated floppy tests passed. Hidden-window tests cover
30 consecutive calls with exactly one disable/enable pair, nested modal scopes,
repainting during waits, error/handle preservation, reentrancy protection,
exceptions, shutdown and original disabled-window state.

Extract into a new folder and run HFVExplorer.exe. Click/browse the same CD to
compare the name, selection and menu display. No formatting is required.
No physical devices or computer control were used; live visual validation is
still needed from the user's manual test. Changes are uncommitted on image-only-x64.
