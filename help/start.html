Current Windows x64 build

Target: Windows 7 SP1 with KB2533623 or a superseding update, Windows 8/8.1, Windows 10 and Windows 11 x64. This compatibility build uses v143 with static MFC/CRT. Older-OS execution is pending VM validation; see WINDOWS-COMPATIBILITY.txt for test status. No legacy CD/floppy driver or Windows 95/98 CD patch is required. The historical driver installation, HPBurner and operating-system instructions do not apply to this build.

  • File > Read volume from floppy saves sector-formatted 720 KB, 1.44 MB or 2.88 MB floppy images. File > Write volume to floppy uses the original compact path-and-drive dialog for 1.44 MB HFS images; writing erases the disk and verifies the result. Ordinary PC/USB drives cannot read Macintosh 400/800 KB GCR disks.
  • File > Format new volume lists removable drives as well as image-file destinations. Selecting a floppy uses the native 1.44 MB HFS formatter with erase confirmation and readback verification. The original File setup dialog layouts are restored, and browsing uses the original 1,000-sector cache. Options > General can enable startup floppy scanning.
  • Native CD browsing is read-only. Selecting a CD drive automatically mounts supported classic HFS, HFS+ / HFSX single-track data CDs in the main tree and list, including Apple-partitioned/hybrid discs. The original 1,000-sector cache and 32-sector read-ahead are restored behind the native reader, with media-change protection. Tools > Dump CD to file saves the complete data track for classic HFS, HFS+, HFSX and hybrid CDs; it does not convert the filesystem. The saved image can be reopened with File > Open volume. Audio, mixed-mode and multisession discs remain unsupported by this raw image path. Tools > Burn CDR/CDRW uses Windows IMAPI2 for blank CD-R/CD-RW media and full verification; HPBurner is no longer used.
  • Classic-HFS copy choices include BinHex 5.0 (MacBinary I) for binary .bin files with both forks. Automatic .bin imports accept MacBinary I and II. BinHex 4.0 remains the separate .hqx text format. Version I preserves only the original high-byte Finder flags and has no header checksum; use MacBinary II for its additional metadata and checksum. The HFS+/HFSX browser continues to import/export raw forks.
  • Tools > Find files works. Copies and storage waits run through the storage worker with progress and overwrite choices. Ordinary copies to a Mac floppy now use direct buffered writes without whole-disk staging or separate readback; a failure can leave partial destination files. Full-image writing retains readback verification. File and context-menu Eject/Reload commands use native Windows requests on selected physical CD/removable drives when supported.
  • Images support 64-bit host offsets, HFS overflow extents and read-only MFS browsing. Classic HFS forks are limited to 2 GiB minus one byte. File > Format HFS+ / HFSX image creates a new HFS+ or HFSX image, journaled by default. Open an HFS+ or HFSX image with File > Open volume to use its separate Unicode browser for file/fork import and export, folder creation, renaming and deletion. Internal journal replay and read/write are supported for HFS+ and HFSX. Catalog and extents trees use incremental updates and linked allocation maps; internal journals grow when needed, subject to contiguous free space. Catalog entries are still loaded into memory. HFSX supports case-sensitive and case-insensitive filenames; choose the format when creating the image. Compressed HFS+/HFSX files using stored data, zlib, LZVN, LZFSE or LZBITMAP can be browsed and exported as decompressed data. File and directory hard links resolve for reading; private backing inodes are hidden. Writing compressed files or hard links is unsupported. Physical HFS+ / HFSX floppy media, compressed DMG containers, external journals and GCR/flux formats are unsupported. Entries with extended attributes or ACLs cannot yet be modified.
  • HFS+, HFSX and read-only MFS images now use the main tree/list alongside classic HFS. Unicode names, 64-bit sizes, sorting, search and ordinary Copy/Paste/Cut, New folder, Rename and Delete commands use shared browser adapters. Read-only and protected items restrict mutation commands. HFS+/HFSX and MFS exports preserve both forks with AppleDouble companions on Windows; explicit raw fork export and import are under File. Folder operations are not whole-tree atomic.
