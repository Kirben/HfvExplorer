HISTORICAL DESIGN - SUPERSEDED
This document describes an earlier implementation. See STORAGE-WORKER.txt,
STORAGE-WAIT.txt and CHANGED-TRACK-COPY.txt for the current implementation.

COPY AND TASKBAR PROGRESS / REFRESH REPAINTING
Branch: image-only-x64; changes remain uncommitted.

Mac-to-Windows file/folder exports now open a progress window after the transfer
mode is chosen. It shows the current source file, that file's percentage, files
successfully copied, total source MiB read and elapsed time. The taskbar button
shows the same current-file progress and clears it when the operation ends.
Preparing/scanning uses an animated indicator rather than a guessed percentage.
The progress bar is per file, not the percentage of the entire directory tree.
Source bytes read can differ from destination size due to conversion/headers.

Automatic mode still chooses raw, text or MacBinary export as before. Resource
forks are counted for modes that export them; resource-only mode counts only
that fork. A file is counted complete only after source/output close succeeds.
No recursive pre-scan is performed. Copy cancellation is not implemented.

The copy window's timers and painting are serviced during driver waits and
between copy chunks; unrelated commands/timers stay deferred to protect the
non-reentrant HFS state. Native I/O now services pending paint even when the
driver call has already completed, preventing fast consecutive reads from
starving repainting. Refresh drive scans also include cooperative paint points.
The stable enabled/focus batching from the previous build remains included.

Validation:
Release and Test builds succeeded. Synthetic recursive Automatic export verifies
nested folders, original data/resource forks in MacBinary output, text conversion,
exact read-byte/file counts, per-file byte bounds and failed output accounting.
Device-wait tests cover paint during both delayed and immediately completed
calls, command deferral, one enable/disable pair across repeated reads, nested
modal scopes, error/handle preservation and shutdown. Simulated floppy tests pass.
No physical devices, settings or computer control were used for validation.
The live progress dialog/taskbar appearance still needs the user's manual test.

Extract to a new folder and run HFVExplorer.exe. Copy a folder from the Mac CD
to a new destination on the hard disk and choose Automatic. Compare the progress
window, taskbar indicator and Refresh repainting. No formatting is needed.

Physical floppy names survive restarts on disk. Startup floppy scanning is off;
View > Refresh discovers the HFS floppy without requiring a prior click on A:.
