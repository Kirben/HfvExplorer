1.44 MB HFS floppy format / image write
2026-11-15

Use Tools > 1.44 MB floppy format/write...
- Select the target drive letter.
- Format HFS creates a complete empty classic HFS filesystem with the chosen
  volume name, then writes all 1,474,560 bytes to the floppy.
- Write image writes a raw HFS image of exactly 1,474,560 bytes. Add files to
  an image using the existing HFS image browser, then write that image to disc.
  The included floppy-test.dsk contains a generated Payload test file with
  data and resource forks; its volume name is FloppyTest.
- Both operations require an explicit erase confirmation naming the drive.
  All original data on that disc will be overwritten. Ordinary disc browsing
  remains read-only; direct file editing on physical floppies is not enabled.
- Low-level format tracks first is optional and unchecked by default. Leave
  it unchecked for an already sector-formatted 1.44 MB disc, including most
  factory-formatted blank discs. It uses IOCTL_DISK_FORMAT_TRACKS and may be
  unsupported by USB drives. An unsupported request fails, without silently
  switching to another formatting operation.

First manual test on A:
1. Close any older HFVExplorer instance and run this build.
2. Open Tools > 1.44 MB floppy format/write..., select A:, and enter MacTest.
3. Leave low-level formatting unchecked. Click Format HFS and confirm the
   explicit erase prompt only if the disc in A: may be erased.
4. Wait for the complete write and readback verification. Close the dialog;
   the volume list refreshes, and the MacTest HFS volume should appear.
5. To test image writing, reopen the dialog, Browse to floppy-test.dsk, select
   A:, click Write image and confirm erasure again. After verification/refresh,
   FloppyTest should contain Payload (data: 8193 bytes; resource: 1025 bytes).
If an operation fails, report its Windows error number and whether writing
started. An access-denied error may require closing programs using the drive
or running HFVExplorer as administrator. A failure after writing starts can
leave an incomplete disc. Do not remove or change the disc during an operation.

Guards and verification
- Only removable drives reporting F3_1Pt44_512, 80 cylinders, 2 heads, 18
  sectors/track and 512-byte sectors are accepted. Other floppy capacities,
  generic flash-drive geometries and fixed disks are rejected.
- The complete source image is prepared/read into memory before confirmation.
  Raw HFS signature/allocation layout and exact image size are checked.
  This is not a general filesystem repair or source-image integrity checker.
- Writable handles are local to the explicit operation. The code requires a
  successful FSCTL_LOCK_VOLUME before FSCTL_DISMOUNT_VOLUME or any writes.
- Writes are aligned and bounded to the full 1.44 MB medium. Media-change
  counters are checked, writes are flushed, and every sector is read back and
  compared with the input. Errors, short writes and mismatches report failure.
- Handles are unlocked/closed on success or failure. No automatic retry
  bypasses write protection, a failed lock, unsupported geometry or an error.
- A drive must already report readable 1.44 MB geometry. Truly unformatted or
  damaged media that cannot supply this geometry is not currently supported.
- This makes a data floppy, not a bootable Macintosh system disk. Macintosh
  400K/800K GCR formats and physical MFS are still unsupported.

DIAGNOSTIC BUILD v1
This build adds failure-stage, byte-offset, sector and completed-track reporting.
A host-side temporary log is written after each operation; its full path appears
in the result dialog. It is only created on a fixed host volume, never a floppy.
The log records the operation trace and final Windows error, requested/transferred
byte counts, zero-based cylinder/head and sector, and completed write/readback counts.
The write size remains one 9,216-byte track. No automatic retries were added.
