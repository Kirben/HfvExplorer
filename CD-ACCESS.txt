HFVExplorer x64: read-only CD access (experimental)
2026-11-15

Run the build from HFVExplorer-x64-cd, leaving the earlier image-only build
available separately. No custom kernel driver or driver installation is used.

Test drive D: from PowerShell
  .\cd-probe.exe D:

The diagnostic opens only the specified optical drive, reports the transport
and HFS volume location, and lists the root directory. It does not write,
eject, lock, format or otherwise modify the disc. If access is denied, rerun
that command in an Administrator PowerShell window. Save/copy its output when
reporting results. A non-HFS disc is reported as an unrecognized volume.

GUI
Run HFVExplorer.exe and press F5 to refresh the volume list. An identified
classic HFS CD should appear as a Mac volume in the left tree. Browse it and
copy files to a normal Windows folder. Image files retain read/write support.
If the probe works only elevated, the GUI may also need administrator rights.
Startup CD discovery can be enabled/disabled in View > Options > General.

Implementation
- A GENERIC_READ device handle performs aligned 2048-byte ReadFile requests.
  Arbitrary HFS 512-byte reads are adapted through an aligned scratch buffer.
- CD TOC lead-out is preferred over the disk-length query, which may describe
  only a mounted volume extent. SCSI READ CAPACITY(10) cross-checks a reported
  capacity smaller than the Apple driver descriptor. Metadata alone never
  expands the actual read bounds. Probe v3 reports all capacity query results.
- Probe v4 also recognizes shortened Apple_HFS partitions when their original
  geometry exceeds the physical medium. The volume view is clipped to the
  readable bytes; its bitmap and initial catalog/extents areas must be present.
  No bytes are fabricated for missing sectors, and extraction beyond the
  physical end fails. A notice reports declared versus readable partition size.
- If ReadFile cannot read sectors, fixed SCSI READ(10) requests are sent via
  Windows' built-in pass-through interface. That IOCTL requires a handle
  opened with read/write access rights, but the code issues ONLY the two
  read commands above. There is no optical WriteFile or SCSI write command.
- The first classic Apple_HFS partition is located in 512/2048-byte Apple
  partition maps. Plain HFS and bounded, mapless legacy hybrid layouts are
  supported. Candidate MDB geometry and all read bounds are checked.
- Separate pseudo-file descriptors adapt the CD to the existing HFS core.
  Each has its own seek position. Writable opens and writes return EROFS;
  the HFS core mounts the volume read-only. Raw hard-disk access,
  disc burning and tray controls remain disabled.
- The application manifest retains Windows-managed display scaling.

Validation performed without physical media
- Native x64 application and diagnostic compiled successfully.
- Existing writable-image roundtrip test passed.
- Synthetic unpartitioned HFS, partitioned hybrids with both map block sizes,
  and mapless hybrids passed reads and actual HFS-core file extraction.
- Both forks were checked byte-for-byte; seeks, EOF bounds, independent open
  descriptors, malformed maps, non-HFS media, normal writable-file passthrough
  and rejection of CD writes/create/delete were tested.
- Full fixture files remained byte-for-byte unchanged after the tests.
- Regression coverage simulates a short Windows length result with a larger
  TOC capacity; the HFS partition is found and its tail reads remain bounded.
- A genuinely shortened HFS fixture mounts and extracts both forks correctly;
  all reads remain bounded, missing sectors are not filled, and a fixture with
  a missing catalog extent is rejected. The complete clipped fixture remains
  byte-for-byte unchanged.
- No physical drive was opened during the automated tests. The user ran
  Probe v4 on D: with LucasArts CD Game Pack: the shortened HFS partition
  mounted and its root listed all seven entries successfully through ReadFile.
  The user subsequently confirmed that the GUI works well. No GUI automation
  was used for this CD implementation.

Limits
Classic HFS only, first HFS partition, volume size below 2 GiB. HFS+, unusual
multisession/audio-first/protected discs and arbitrary optical layouts are
not claimed supported. This remains an unofficial experimental port.

Build and tests
  .\build-x64.ps1
  .\build-x64.ps1 -Test
The latter uses generated, disposable fixtures; it never opens optical drives.
