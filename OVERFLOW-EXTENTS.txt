Classic HFS overflow-extents support
2026-11-15

The GUI reader now follows the extents-overflow B-tree after a fork's three
inline extent descriptors. Lookup uses file ID, unsigned fork type and the
cumulative logical allocation-block number. Additional mappings are cached
per open fork and preserve 64-bit host-image offsets.

This applies to ordinary data/resource forks and the catalog file. The
overflow tree opens before the catalog. A fragmented overflow tree can
bootstrap its own mappings from its already readable leaf chain; recursive
or inaccessible self-mappings fail instead of looping. The hfsutils core
also uses this bootstrap when reading its own extents file.

Node sizes, record offsets, index heights, node counts, extent ranges and
forward progress are checked by the new GUI traversal. Missing or invalid
mappings stop reads at the mapped bytes. No missing sectors are invented.
This is not a general filesystem checker or recovery tool.

Tests
Run .\build-x64.ps1 -Test in the source checkout. It uses disposable images
and headless storage tests, without windows, drive discovery or optical I/O.

- The hfsutils writer creates 16 files, each with ten noncontiguous extents
  in both data and resource forks. Each fork needs three overflow records.
- A genuine catalog containing 116 files is relocated into ten extents.
  The core reopens it and verifies the patterned file forks independently.
- The GUI reader checks every fragmented fork byte-for-byte and compares
  the entire catalog against the core reader's saved bytes. Catalog leaves
  are enumerated and their file records are used to open the actual forks.
- The overflow tree has multiple index branches. Tests cover backward and
  direct late seeks, inline/overflow transitions, overflow-record boundaries,
  fork identity, EOF clipping and repeated reads.
- A second image relocates the overflow tree itself into ten extents. The
  core and GUI readers compare it with its pre-relocation bytes; both read
  resource data through the fragmented catalog and overflow tree.
- Corrupted copies test missing records, zero-progress extents, out-of-volume
  extents, invalid record offsets and cyclic index links in the GUI reader.
- Existing small-image, 6 GiB read/write and synthetic read-only CD tests run
  in the same suite. No user media is modified.

Scope remains classic HFS. MFS, HFS+ and HFSX are not added. Physical CDs
remain read-only. Existing compiler conversion/deprecation warnings remain.
