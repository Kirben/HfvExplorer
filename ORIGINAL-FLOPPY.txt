Original floppy behavior restored in the Windows x64 port
========================================================
File > Format new volume and File > Read/Write volume to/from floppy use the
original resource templates, verified against ObsoleteMadness upstream with
only line endings normalized. No replacement floppy setup windows remain.
Detected drive letters replace static A/B assumptions behind the same controls.
Progress and erase confirmation remain separate from those original layouts.

The reader now reuses the original cache.cpp implementation and its 1,000
512-byte sector slots/replacement policy. Cache hits avoid physical sector
reads; contiguous misses are batched. The original read-ahead setting was one
sector, so unrelated tracks are not prefetched. The native transport retains
a 32 KiB maximum transfer size. Reads use FILE_FLAG_RANDOM_ACCESS, matching the
old NT path, while still opening the browsing handle read-only.

Handles are reused while references remain open. Closing, reopening, errors,
media changes and suspension before writing invalidate the sector cache.
The old cache's entry count is reset when fresh storage is allocated, and
partial allocation failure is handled safely.

One media-generation check occurs per logical read, including cache hits;
every new physical transfer is checked again before its data is cached or
returned. The duplicate pre-check between consecutive transfer chunks is gone.
The original did not have these same checks. Full-image write verification and media-change protection are retained. Ordinary
file copies now use scoped direct writes and an original-style 64 KiB buffer,
with no separate readback pass. No Windows 95/98 custom driver or unsafe image
truncation behavior is restored. See FLOPPY-FILE-COPY.txt.

Synthetic checks: 100 repeated reads issue zero additional sector reads;
cache capacity/eviction, overlapping and large reads, exact verification-call
counts, media changes, errors and reopen invalidation; original dialog layout,
B/Z drive binding, native write/readback and unsupported flush handling, slow
progress UI and owner restoration. Full simulated storage regressions pass.
Real USB-floppy timings have not been measured for this update.
